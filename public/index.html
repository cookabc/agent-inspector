失控日志 展开看原因与复现命令

Agent 会把每条命令的 stdout 完整落盘到 <root>/cli/exec/<会话>/call_<id>-stdout.log。这个路径就在被审计的目录里面，于是它自己也会成为搜索的目标。

真实发生过的一次：某个只读的 Explore 子 Agent 执行了下面这样一条命令（搜索模式已脱敏）——

grep -RIn --exclude-dir=.git \
     -E '<某个内部指标名>' \
     ~/.zcode/cli/exec

它搜索的目录里，正躺着这条命令自己的输出文件。grep 一边读、一边匹配到 harness 正在写入的内容，输出被下一轮再次匹配 —— 于是每转一圈就嵌套一层。证据是日志的结尾，同一条路径被层层套住，行号以 8 递减：

…/call_<id>-stdout.log:19977:…/call_<id>-stdout.log:19969:…:19961:…

另一种放大不需要自引用：搜的是 cli/agents/**/transcript.jsonl，而每条记录都保存了发给模型的完整请求体，单行就有几百 KB，匹配一次就是几百 KB 的输出。

要避免复发：别让 Agent 把 ~、~/.zcode、~/.claude 当 grep -R 的搜索根。
